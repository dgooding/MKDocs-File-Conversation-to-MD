02 · Invariants

Engineering invariants

These constraints are project architecture, not suggestions. New work should preserve them unless a checkpoint explicitly changes the contract.

One authoritative conversion function per format. API, batch, desktop packaging, and future jobs call convert_docx or convert_pdf; do not fork conversion behavior.
Exact direct/API parity. HTTP output must equal direct function output byte-for-byte for the same input.
Technical success is not fidelity approval. Automated structure and coverage metrics never become “human reviewed.”
Native semantics first. Use native document structure and PDF text geometry; targeted OCR/fallback only when measured extraction is weak; full-page visual fallback last.
Optional providers fail closed. Missing OCR or experimental converters cannot break unrelated formats.
Diagnostics stay outside Markdown. Route, warnings, duration, confidence, and review reasons belong in metadata, not published content.
Real pilot documents remain local. Do not commit or upload internal documents without explicit approval.
One approved checkpoint at a time. State purpose/files/validation, implement narrowly, validate, report, and stop for approval.

Statelessness

  • Converters accept bytes and return str.
  • DOCX preparation uses BytesIO; it never modifies the source.

06 · DOCX

DOCX conversion pipeline

convert_docx(content: bytes) -> str is the sole DOCX conversion authority.

  1. Reject empty content. Raise ValueError("DOCX content cannot be empty").
  2. Open an in-memory document. python-docx parses BytesIO(content).
  3. Infer only missing semantic headings. Existing Heading/Title styles are left alone; list styles and numbered paragraphs are excluded.
  4. Prepare a temporary copy. For inferred headings only, apply Heading N and clear run-level bold, size, and color in the temporary document to avoid duplicate Markdown styling.
  5. Convert with MarkItDown. Disable plugins, supply extension/MIME metadata, and set keep_data_uris=True.
  6. Return MarkItDown Markdown unchanged. API and batch consume the exact same result.

Heading inference rules

Preserved and bounded behavior

Validated

  • Bold/italic emphasis.
  • Bulleted and numbered lists.
  • Unicode and external hyperlinks.
  • Tables and embedded raster images.
Known boundary
  • Markdown is semantic, not pixel-exact Word layout.
  • Colors, exact spacing, pagination, and positioned objects flatten.
  • One deterministic special-character fixture remains review-flagged.
  • Native editable Office chart objects are not independently reconstructed.
07 · PDF

Native PDF conversion pipeline

convert_pdf(content: bytes) -> str first attempts the geometry-aware native route and uses MarkItDown only as a final converter-level fallback.

Document pre-pass

  • Open the byte stream with pdfplumber and pypdfium2.
  • For each page, collect text lines in the top 10% and bottom 8%.
  • Normalize candidate furniture by lowercasing, collapsing whitespace, and replacing digits with #.
  • Text repeated at least twice in those regions is removed from page output.
  • Maintain a document-wide SHA-256 set for image deduplication.

Per-page extraction

  1. Extract and reserve table boxes. pdfplumber identifies tables first; overlapping text lines are not emitted twice.
  2. Extract formatted lines. Character data provides text, x/y rectangles, font name, size, weight, and annotation overlap.
  3. Estimate body size and margin. Body size is the median visible character size; body-left is the minimum x-position among body-sized lines.
  4. Classify blocks. Detect lists, headings, form-like bold fields, paragraph continuations, and separate paragraphs.
  5. Render images. Render page at 2×, crop source image boxes, rescale PDF points to CSS pixels at 96/72, optimize PNG, hash, deduplicate, and embed as base64.
  6. Assemble in reading order. Sort blocks by vertical top and join with blank lines; add page comments after page 1.

Formatting and structure rules

FeatureImplementation
Word spacingInsert a space when the x-gap exceeds max(0.8, character_size × 0.08).
Style groupingGroup adjacent characters by bold, italic, and URI; output **, *, or ***.
Link matchingMatch character rectangle to annotation rectangle; URL-encode while preserving URI-safe characters.
Ordered listRecognize 1. and 1).
Bullet listRecognize common circle/square/private-use glyphs and + * -; indented o is accepted beyond body-left + 8 pt.
List nestingTrack contiguous x-position levels with 3-point tolerance; reset after a vertical gap > body size ×1.25.
Large headingSize ≥ max(18, body ×1.55); first qualifying page-1 heading is H1, later large headings H2.
Left headingx ≤ body-left +3, text ≤90 chars, no sentence-ending punctuation, and size/weight threshold.
Paragraph joinVertical gap ≤ max(7, body ×0.8) and x difference ≤ max(3, body ×0.25).

Table normalization

  • Normalize whitespace and escape literal pipes.
  • Drop columns empty in every row.
  • For sparse grids with at least four columns and at most two populated cells per row, merge visual halves into two logical columns.
  • A one-column table becomes a blockquote/callout.
  • Rows with one populated value split table segments and become bold section labels.
  • Single-row multi-column grids receive an empty Markdown header rather than flattening to text.

Image and annotation behavior

  • Output image dimensions are source-proportional, avoiding the original 2× preview inflation.
  • Document-wide image hashes suppress repeated mastheads but preserve distinct screenshots.
  • HTTP, HTTPS, intranet, SharePoint, and mailto annotations are recovered.
  • Image alt text is currently generic: Image from page N; semantic caption generation is deferred.

Known PDF boundaries

  • Multi-column reading order follows pdfplumber extraction; there is no general column reflow engine.
  • Password-protected or malformed PDFs may fall through to MarkItDown and can still fail.
  • Complex merged-cell tables are normalized for readability, not reconstructed as exact layout.
  • Vector graphics and charts are preserved through available image/page rendering, not converted into editable chart data.
  • Page comments preserve location but are not a visual page-layout contract.
08 · OCR

Scanned PDF detection and optional OCR

OCR is an adapter, not a mandatory dependency. Native PDFs never require it.

Page classification

needs_ocr = native_visible_character_count < 40
            and largest_image_area / page_area > 0.55

This threshold correctly flagged the deterministic image-only fixture and produced zero false-positive pages across all eight born-digital pilot PDFs.

Tesseract provider discovery

  1. Use explicit TESSERACT_CMD when set.
  2. Check PATH.
  3. Check standard 64-bit and 32-bit Windows install paths.
  4. Check the LocalAppData program path.
  5. Probe --version with a 4-second timeout.
  6. Return None when absent or invalid.

OCR invocation

tesseract stdin stdout -l eng --psm 6
  • Input is the 2× rendered page converted to RGB PNG in memory.
  • Timeout is 60 seconds.
  • Non-zero exit, OS error, timeout, or empty output returns None.
  • OCR paragraphs are normalized and escaped before Markdown insertion.
  • If OCR is unavailable, the page image remains in output; content is not silently discarded.
Current state: Tesseract is not installed on the workstation, and real scanned-document OCR quality has not been evaluated. Do not claim searchable scanned-PDF support for v1 until Milestone 18 completes.
09 · Batch

Batch orchestration and manifest

Batch conversion is intentionally thin. It calls the same converter mapping used by the single-file route and isolates failures by input.

Limits and routing

  • API accepts at most 25 uploaded files.
  • Total uploaded bytes must not exceed 100 MB.
  • Supported suffixes are case-insensitive .docx and .pdf.
  • There is currently no explicit application-level single-file byte limit.
  • Conversion is sequential and in memory; concurrency/load behavior is not benchmarked.

Per-file statuses

unsupportedSuffix not DOCX/PDFManifest only
emptyZero-byte contentManifest only
errorConverter raisedManifest only; other files continue

Output naming

Output names use the input stem plus .md. Case-folded collisions receive -2, -3, and so on. An empty stem becomes document.md.

11 · UI

Browser UI and renderer safety

The frontend is framework-free HTML, CSS, and JavaScript packaged inside the Python wheel.

Single page

  • Accepts one DOCX/PDF.
  • Calls /api/convert.
  • Places Markdown in an editable textarea.
  • Debounces preview rendering by 200 ms.
  • Downloads edited Markdown using a Blob.

Batch page

  • Accepts multiple DOCX/PDF files.
  • Displays selected filenames and approximate KB.
  • Posts all files in one request.
  • Downloads the server-generated ZIP using Content-Disposition filename.
  • Reports completion or API error in an ARIA live region.

Renderer configuration

  • CommonMark preset.
  • Raw HTML disabled.
  • Linkify disabled.
  • Typographer disabled.
  • Markdown tables enabled.
  • Unsafe javascript: links do not render as active links.
  • Raster image data URIs render; SVG data URIs are rejected.

The preview is intentionally functional and restrained. It is not a pixel-perfect Word/PDF viewer.

12 · Quality

Quality model and corpus evidence

Quality is tracked in two independent dimensions: technical operation and fidelity review.

Technical

Machine-verifiable

  • Converter completes or returns controlled failure.
  • Output is structurally testable.
  • Direct and API output are exact.
  • Expected links/images/tables/text tokens are present.
  • Package and deployment policies are testable.
Fidelity

Human decision

  • Does the output communicate the same meaning?
  • Are hierarchy and reading order acceptable?
  • Are images and tables useful in context?
  • Are known Markdown layout losses acceptable?
  • Status remains not_reviewed until a person decides.

DOCX corpus

  • 10 deterministic documents.
  • Covers semantic/visual headings, emphasis, bullets, numbering, Unicode, hyperlinks, tables, and images.
  • Technical pass rate: 1.0.
  • Direct/API parity rate: 1.0.
  • 9 clean; 1 review-required special-character rendering case.

PDF corpus

  • 8 real operational documents totaling 45 pages.
  • 45 unique source images and 24 unique source URIs.
  • 8 detected table regions.
  • 8/8 exact direct/API parity.
  • 8/8 link completeness.
  • 8/8 unique-image parity.
  • 8/8 clean automated gates after excluding deliberately removed repeated page furniture.

Visual review process

  1. Rasterize every source PDF page into contact sheets.
  2. Convert each PDF with the authoritative converter.
  3. Render exact Markdown into page-split browser contact sheets.
  4. Compare source pixels with rendered output for hierarchy, sequence, images, links, lists, callouts, and tables.
  5. Repair universal algorithm issues, then rerun focused tests and all corpus metrics.

14 · Decisions

Experiments and rejected alternatives

Alternatives were evaluated against the same portability and quality constraints rather than added speculatively.

MarkItDown retained for DOCX

The validated DOCX route is stable, image-capable, API-parity tested, and already covered by a deterministic corpus.

Native pdfplumber/pypdfium2 route retained for PDF

Actual pilot geometry showed font hierarchy, annotations, image rectangles, and tables were recoverable without OCR or heavyweight model integration.

Marker parked

Marker 2.0.0 was isolated in .marker-spike. Its Windows DOCX path encountered GTK/Pango dependencies through WeasyPrint. Do not integrate, extend, or delete the spike without approval.

Word COM PDF→DOCX rejected

The simplest five-page PDF did not create a DOCX within 120 seconds and left an owned WINWORD process requiring forced cleanup. The route is session-dependent, Windows-specific, and incompatible with Docker/OpenShift goals. Evidence is in review\pdf-word-com-comparison.json.

External Markdown benchmark

Existing Markdown outputs in Downloads were analyzed for heading hierarchy, nested lists, image naming, links, and furniture removal. Useful semantic patterns were noted. Raw inline HTML styling was intentionally not adopted because the preview renderer disables raw HTML for safety.

15 · Deploy

Docker and OpenShift design

Deployment files are implemented and statically/package validated. No local container runtime is available, so an actual image run remains Milestone 17.

Dockerfile

  1. Copy uv 0.12.5 from the official uv image.
  2. Use python:3.12-slim-bookworm builder.
  3. Copy only pyproject.toml, uv.lock, and src.
  4. Run uv sync --frozen --no-dev --no-editable.
  5. Use a clean Python slim runtime and install libgomp1.
  6. Copy only the virtual environment.
  7. Set group ownership/permissions for OpenShift arbitrary UID compatibility.
  8. Set HOME=/tmp and cache under /tmp.
  9. Expose 8080; run as UID 1001.
  10. Healthcheck /health; start one Uvicorn worker.

OpenShift security posture

  • runAsNonRoot: true
  • allowPrivilegeEscalation: false
  • Drop all capabilities.
  • RuntimeDefault seccomp.
  • Read-only root filesystem.
  • Ephemeral emptyDir mounted at /tmp.
  • Readiness and liveness on /health.
  • 250m CPU / 512Mi memory requests.
  • 2 CPU / 2Gi memory limits.
  • TLS edge Route with HTTP redirect.

Verified without a container runtime

  • Wheel built successfully.
  • Non-editable isolated install imported the package.
  • All five static assets were present in the wheel.
  • /health worked from the isolated install.
  • Static policy tests validate Docker and OpenShift controls.

Required Milestone 17 validation

  • Build and run the image.
  • Run with arbitrary UID and read-only root filesystem.
  • Exercise single and batch conversions.
  • Measure startup, image size, memory, and conversion behavior.
  • Scan dependencies/image for vulnerabilities and produce an SBOM if required.
  • Push to approved registry and perform OpenShift rollout.

18 · Security

Security and data handling

Current controls are appropriate for a local/internal pilot, not an exposed multi-user service.

Implemented controls

  • Uploads are processed in memory and not persisted by application code.
  • Raw HTML is disabled in preview rendering.
  • Unsafe JavaScript links and SVG data URIs are rejected.
  • API returns generic conversion errors rather than exception detail.
  • Batch limits file count and aggregate bytes.
  • Container runs non-root with restricted OpenShift security context.
  • Build context excludes private review documents and local environments.

Open controls before hosted release

  • Authentication and authorization.
  • TLS/ingress policy and network exposure.
  • Retention, privacy classification, and deletion policy.
  • Malware/content scanning.
  • Single-file size limit, request timeout, concurrency controls, and rate limiting.
  • Privacy-safe structured logs, request IDs, audit events, and telemetry.
  • Dependency/image vulnerability scanning, SBOM, signing, and patch policy.
  • Abuse testing for malformed archives/documents, decompression bombs, and memory pressure.

Definition of done for a conversion change

  • Focused regression test covers the defect/feature.

  • No unrelated format regresses.
  • Full tests pass.
